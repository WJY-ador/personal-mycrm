# 설정 · 지도

> 기준: 2026-11-04 구버전 `7e93eef` 관찰·코드 조사. 최신 main은 React로 전환되어 현재 화면과 차이가 있을 수 있다. 최신 화면 실측 전 개선안은 가설이다.

## 사실

가짜 계정의 지도는 `들어오는 것 / 내 손 대기 / 쌓이는 재료` 세 열과 원문·대조 링크, 샘플 카드 한 건을 보여 줬다. 다량 카드·모바일·상호작용 결과는 미확인이다. [설정 목록](https://github.com/WJY-ador/personal-mycrm/blob/7e93eef/server/app.html#L3190)

## 판단

자료가 어떤 과정을 거치는지 세 열로 설명하는 점은 유지할 만하다. 각 열이 실제 상태 변경을 허용하는 보드인지 사용자가 혼동하는지는 시험해야 한다.

| 현재 | 제안 | 이유 |
|---|---|---|
| 세 열에 카드와 링크가 있다 | 카드 hover·focus와 링크 목적지를 명확히 하고 링크 이동 후 돌아올 위치를 보존하는지 확인한다. | 흐름 설명과 실제 탐색을 연결한다. |
| 카드 간 드래그 목적이 확인되지 않았다 | 카드 드래그를 보류한다. 단계 이동이 실제 상태 변경이라면 권한·확정·되돌리기 계약부터 설계한다. | 시각적 흐름을 임의의 데이터 이동으로 오해하지 않도록. |
| 많거나 좁은 화면은 미실측이다 | 좁은 화면에서 열 순서와 스크롤을 확인한다. 이동 효과는 길고 장식적인 연쇄 동작보다 즉시 반응을 우선한다. | 흐름을 잃지 않고 탐색할 수 있게 한다. |

## 제안

다량 가짜 데이터와 모바일에서 흐름을 따라가고 원문으로 이동·복귀하는 과정을 확인한다. [Apple 드래그 기준](https://developer.apple.com/design/human-interface-guidelines/drag-and-drop)
