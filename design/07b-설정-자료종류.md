# 설정 · 자료 종류

> 기준: 2026-11-04 구버전 `7e93eef` 관찰·코드 조사. 최신 main은 React로 전환되어 현재 화면과 차이가 있을 수 있다. 최신 화면 실측 전 개선안은 가설이다.

## 사실

샘플 자료 종류 화면에는 라벨과 함께 내부 API 키가 보였다. 목록은 표준과 커스텀 자료를 구분한다. [자료 종류](https://github.com/WJY-ador/personal-mycrm/blob/7e93eef/server/app.html#L3601) 개별 자료 상세와 실사용자 검증은 하지 않았다.

## 판단

내부 키가 일반 사용자에게 필요한지 확인해야 한다. 라벨과 키가 혼란을 준다는 것은 가설이며 기술적 연결에 키가 필요한 사용자도 있을 수 있다.

| 현재 | 제안 | 이유 |
|---|---|---|
| 자료 라벨과 내부 키가 함께 보인다 | 사람이 이해하는 이름을 우선하고, 키는 사용 필요성을 확인해 상세나 설명으로 옮기는 안을 비교한다. | 일반 탐색과 기술 식별의 목적을 구분한다. |
| 표준·커스텀 카드가 있다 | 클릭·키보드 focus·선택 상태를 구분하고, 빈 상태에는 기존 생성 경로를 명시한다. 전환은 반복 이용을 방해하지 않도록 즉시 반응을 우선한다. | 어떤 자료를 열고 어디서 추가하는지 알 수 있다. |
| 자료 종류 간 이동 목적은 미확인 | 카드 드래그를 보류한다. | 자료 종류 간 이동은 관계나 데이터 구조를 바꾸는 행위일 수 있다. |

## 제안

일반 사용자와 관리자가 키를 실제로 쓰는 장면을 확인한 후 시각 위계를 정한다. [버튼 위계](https://fluent2.microsoft.design/components/web/react/core/button/usage/)
