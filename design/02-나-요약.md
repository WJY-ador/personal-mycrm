# 나 · 요약

> 기준: 2026-11-04 구버전 `7e93eef` 관찰·코드 조사. 최신 main은 React로 전환되어 현재 화면과 차이가 있을 수 있다. 최신 화면 실측 전 개선안은 가설이다.

## 사실

임시 신규 계정에서 표시 이름을 입력한 뒤 13주 활동, 자료 종류별 건수, 기다리는 결정과 최근 변경을 확인했다. 빈 요약에 0과 잠금 표시, 자료가 들어오면 볼 수 있다는 문구가 있지만 첫 글을 남기는 직접 안내는 보이지 않았다. 가짜 후보는 기다리는 결정에서 검토 목록으로 이동했다. 시험용 기록·후보는 DB API로 만들었다. 실제 AI 연결이나 대화 생성은 검증하지 않았다. [집계 화면 코드](https://github.com/WJY-ador/personal-mycrm/blob/7e93eef/server/app.html#L3129)

기존 [첫 하루 안내](../guides/09-hosted-start.md#L5)는 외부 AI 대화에 MyCRM MCP를 연결하고 표시 이름을 정한 다음, `기록 남길게` → `후보 뽑아 줘` → 웹에서 원문과 대조하는 순서를 설명한다. 질문은 선택이며 나중에 정해도 된다. 이 MCP 경로에 PC 연결 장치는 필수라고 안내하지 않는다. 웹 안의 `대화`는 별도 기능으로 PC 연결·로컬 에이전트 실행·본인 구독 CLI가 필요하다. [웹 대화 조건](../guides/09-hosted-start.md#L29)

## 판단

현재 상태와 검토할 판단을 함께 보여 주는 구성은 유지한다. 빈 화면에서 **첫 자료가 어떤 경로로 들어오는지** 바로 파악하기 어려울 가능성이 있다. 실제 신규 사용자 시험은 하지 않았다.

| 현재 | 제안 | 이유 |
|---|---|---|
| 신규 계정의 수치가 대부분 0이고 첫 기록 동선이 보이지 않았다 | 자료가 없을 때만 `AI 대화 연결 → 기록 남기기 → 후보 검토`를 짧게 소개하고 기존 첫 하루 도움말로 연결하는 안을 시험한다. 외부 AI의 MCP 연결과 PC가 필요한 웹 대화를 구분한다. | 숫자보다 첫 행동을 찾기 쉽고 별도 기능의 실행 조건을 혼동하지 않는다. |
| 기다리는 결정에서 목록으로 이동한다 | 클릭 직후 반응과 로딩을 표시하고, 돌아왔을 때 선택 위치를 유지할 필요가 있는지 다량 자료에서 시험한다. | 어디로 이동했고 어디서 돌아왔는지 알기 쉽다. |
| 히트맵·건수·상태가 같은 화면에 있다 | 읽는 순서를 제목→다음 행동→요약 근거로 비교하고, 기존 색상만으로 상태를 구분하지 않는다. | 필요한 행동이 집계에 묻히지 않도록. |
| 순서 변경은 별도 설정에 있다 | 요약 화면 자체의 드래그는 보류한다. 기존 설정의 순서 변경 효과를 먼저 평가한다. | 보기와 배치 편집을 섞지 않고 기존 저장 경계를 유지한다. |

## 제안

| 순서 | 현재 가능한 경로와 조건 | 검토할 변경 | 검증 방법 |
|---|---|---|---|
| 1 | 웹에서 표시 이름을 정한다. | 빈 요약에 도움말 진입점을 둔다. | 초보 사용자가 다음 행동과 도움말을 찾는지 관찰한다. |
| 2 | 외부 AI에 MCP를 연결하고 대화에서 기록을 남긴다. 질문은 선택이다. | 안내 문구에 외부 AI 연결 경로를 분명히 쓴다. | 실제 연결과 기록 생성은 아직 미검증이므로 가짜 계정으로 따로 확인한다. |
| 3 | 대화에서 후보를 만든 뒤 요약의 기다리는 결정을 연다. | 기존 검토 진입점을 안내에서 가리킨다. | 여러 후보에서도 목록의 위치와 돌아오기 흐름을 확인한다. |
| 별도 | 웹 내 대화는 PC 연결·로컬 에이전트·본인 구독 CLI가 필요하다. | MCP 기록에 PC 연결이 필수인 것처럼 표시하지 않는다. | 연결된 장치 유무별 안내를 비교한다. |

신규 계정과 자료가 많은 계정에서 첫 행동·소요 클릭을 기록한다. 도움말 링크는 키보드 focus와 모바일 줄바꿈을 확인하고 클릭은 즉시 반응시키되 움직임 줄이기 설정을 따른다. 안내는 기존 경로를 가리키며 새 수집·쓰기 API를 만들지 않는 방향을 우선한다. [버튼 위계](https://fluent2.microsoft.design/components/web/react/core/button/usage/)
