# 설정 · 페이지 레이아웃

> 기준: 2026-11-04 구버전 `7e93eef` 관찰·코드 조사. 최신 main은 React로 전환되어 현재 화면과 차이가 있을 수 있다. 최신 화면 실측 전 개선안은 가설이다.

## 사실

나의 하위 탭과 요약 블록 재정렬이 이미 구현돼 있다. 마우스·터치 드래그와 `Alt + 방향키`를 지원하고 저장·실패 복원·충돌 처리 코드를 갖는다. [렌더링](https://github.com/WJY-ador/personal-mycrm/blob/7e93eef/server/app.html#L3237) · [입력 처리](https://github.com/WJY-ador/personal-mycrm/blob/7e93eef/server/app.html#L3317)

가짜 계정에서 `Alt+↓`를 실행해 순서 변경과 `저장했어요` 알림을 확인했다. 구버전의 접근성 트리와 DOM에서 항목 이름에 HTML 문자열이 섞이는 것을 확인했다. [이름 생성](https://github.com/WJY-ador/personal-mycrm/blob/7e93eef/server/app.html#L3243) 390×844 에뮬레이션에서 설정 메뉴 줄바꿈과 세로 목록을 확인했다. 최신 React 코드의 [이름 생성](../server/ui/src/features/me/layout/DndList.tsx#L53)은 텍스트를 사용하며 [테스트](../server/ui/src/features/me/layout/LayoutScreen.test.tsx#L48)는 순수 이름을 검사한다. 최신 화면 실측, 실기기 터치·실제 스크린리더·실패 복원은 미확인이다.

## 판단

사용자가 직접 순서를 바꾸는 이 화면은 드래그에 적합하다. 이미 존재하는 키보드 대안과 즉시 저장 흐름을 보존해야 한다. 과거 HTML 노출은 보조기기에 영향을 줄 수 있다. 최신 코드는 정정된 정황이므로 수정이 필요하다고 단정하지 않고 실제 화면과 스크린리더에서 재검증한다.

| 현재 | 제안 | 이유 |
|---|---|---|
| 구버전 접근성 이름에 HTML 문자열이 들어갔다. 최신 코드는 텍스트를 쓴다 | 최신 화면에서 접근성 이름과 실제 스크린리더 동작을 재검증한다. 실제 스크린리더로 순번 변경 전후를 확인한다. | 코드 문자열이 읽힐 위험을 줄인다. |
| 키보드 Alt+↓와 저장 알림을 확인했다 | 포커스 테두리와 변경된 위치, 저장 결과를 키보드·보조기기에 전달하고 실패 시 복원되는지 시험한다. | 드래그 없이 같은 결과를 확인할 수 있다. |
| 터치는 손잡이에서 시작하도록 코드에 있다 | 실제 손가락으로 손잡이 발견성·잡기 크기·스크롤 충돌·취소를 시험한다. | 에뮬레이션만으로 터치 조작 품질을 판단할 수 없다. |
| 이동·저장 효과 체감은 미측정 | 잡은 항목·놓을 위치를 명확히 표시하고, 이동은 짧게·중단 가능하게 한다. 움직임 줄이기에서는 위치를 즉시 반영한다. | 결과와 목적지를 알리고 불필요한 대기를 줄인다. |

## 제안

우선 접근성 이름 재현을 자동 점검과 실제 스크린리더로 검증한다. 이후 마우스·터치·키보드와 저장 실패·다른 탭 충돌을 시험한다. 변경은 기존 레이아웃 PUT/복원 계약을 유지한다. [Apple 드래그 기준](https://developer.apple.com/design/human-interface-guidelines/drag-and-drop)
