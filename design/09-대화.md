# 대화 서랍

> 기준: 2026-11-04 구버전 `7e93eef` 관찰·코드 조사. 최신 main은 React로 전환되어 현재 화면과 차이가 있을 수 있다. 최신 화면 실측 전 개선안은 가설이다.

## 사실

코드상 대화 기능은 조건에 따라 나타나고, 장치가 없을 때는 새 대화 버튼 대신 안내가 표시된다. 넓은 화면은 오른쪽 서랍, 768px 미만은 전체 화면 구성이며 입력·상태·확인 카드가 있다. [레이아웃](https://github.com/WJY-ador/personal-mycrm/blob/7e93eef/server/app.html#L834) · [대화 연결](https://github.com/WJY-ador/personal-mycrm/blob/7e93eef/server/app.html#L4078) 실제 장치를 연결한 대화·저장·만료 흐름은 확인하지 않았다.

## 판단

대화는 자료를 만들고 확인하는 흐름과 연결되므로, 서랍의 장식보다 작성한 내용과 상태의 보존이 우선이다. 코드에 있는 조건별 안내가 사용자에게 이해되는지는 실측 전 가설이다.

| 현재 | 제안 | 이유 |
|---|---|---|
| 넓은 화면은 서랍, 모바일은 전체 화면 | 열 때 현재 화면과의 관계를 알리고 닫은 뒤 포커스를 호출 위치로 돌리는지 확인한다. 패널 이동은 150–250ms 후보, 감소 설정 시 즉시 전환을 시험한다. | 공간 관계와 키보드 맥락을 지킨다. |
| 장치 없을 때 안내가 나온다 | 연결 방법과 재시도 가능 시점을 실제 상태에 맞게 설명하는지 검증한다. | 불가능한 동작을 기대하게 하지 않는다. |
| 입력·작업·확인 카드가 코드에 있다 | 전송 중·완료·만료·실패를 구별하고, 실패 시 입력과 미확정 내용을 보존하는지 시험한다. | 장시간 작업 중 중복 전송과 내용 손실을 막는다. |
| 드래그로 대화를 이동할 목적은 확인되지 않았다 | 대화 메시지·판단 확정에 드래그를 추가하지 않는다. | 입력과 확정의 의미를 분명하게 유지한다. |

## 제안

가짜 장치로 연결·응답 지연·확인·실패·만료를 각각 실측한다. 변경은 기존 대화 세션과 사용자 확인 계약을 유지한다. [모션 기준](https://atlassian.design/foundations/motion) · [진행 상태](https://developer.apple.com/design/human-interface-guidelines/progress-indicators)
