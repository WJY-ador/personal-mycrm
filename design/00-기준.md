# 공통 UX·UI 평가 기준

> 기준: 2026-11-04 구버전 `7e93eef` 관찰·코드 조사. 최신 main은 React로 전환되어 현재 화면과 차이가 있을 수 있다. 최신 화면 실측 전 개선안은 가설이다.

## 사실

호스팅 앱은 밝은 회백색과 녹색 강조, AI 상태의 보라색, 근거 강조의 노란색을 사용한다. 버튼 배경·테두리·글자색 전환은 120ms이며 `:focus-visible`과 `prefers-reduced-motion` 대응이 코드에 있다. ## 판단

유지보수·사용자 편의·단순함·편리함을 함께 본다. 같은 역할의 상태는 한 방식으로 전달한다. AI 후보·확정 판단·원문은 색만이 아니라 문구로 구분한다. 속도 수치는 제품 실측이나 승인된 규칙이 아니다.

| 현재 관찰 또는 확인 항목 | 제안 | 이유 |
|---|---|---|
| 버튼의 상태 전환은 코드상 120ms | hover는 색·테두리 변화, press는 즉각적인 미세 반응을 후보로 삼는다. 키보드 focus는 별도 윤곽으로 유지한다. | 동작을 알리되 키보드 초점을 hover에 의존하지 않기 위해. |
| 비활성 상태의 원인은 화면마다 확인 필요 | disabled는 사유와 해제 방법을 가까이 설명한다. 처리 중은 중복 실행을 막고 진행 문구를 둔다. | 클릭 불가와 처리 중을 구분하기 위해. |
| 일부 화면은 저장 알림 제공 | 성공에는 대상과 결과를, 실패에는 유지된 입력과 재시도 경로를 표시한다. | 사용자가 다시 입력하거나 중복 요청하지 않도록. |
| 모션 코드는 있으나 체감·프레임 미측정 | 자주 쓰는 탭·키보드 이동은 지연 없이, 가끔 여는 패널은 짧은 진입을 후보로 검토한다. 감소 설정에서는 이동 효과를 제거한다. | 작업을 늦추지 않으며 상태 변화는 전달하기 위해. |
| 화면 전환 시간은 미측정 | 실험 시작점으로 클릭 반응 100–150ms, 패널 진입 150–250ms를 사용성 시험에서 비교한다. | [Atlassian 예시](https://atlassian.design/foundations/motion)를 제품에 맞게 검증하기 위해. |

## 드래그 판단

사용자가 순서나 위치를 직접 바꾸는 일이 빈번하고, 놓을 대상과 결과가 분명할 때만 검토한다. 이동 중 위치, 저장 중·성공·실패, 실패 시 복원과 키보드·터치 대안을 함께 설계한다. 관계 연결이나 판단 확정을 드래그로 대신하지 않는다. 드래그 하나를 추가할 때 데이터 변경 권한과 기존 API, 충돌 처리, 되돌리기 비용을 검토한다. [Apple 가이드](https://developer.apple.com/design/human-interface-guidelines/drag-and-drop)

## 제안: 공통 검증

각 화면을 빈 상태·많은 자료·처리 중·실패에서 확인하고, 키보드 포커스 이동, 실제 스크린리더, 390px 안팎 및 터치, 다크 테마와 움직임 줄이기를 점검한다. 이 문서의 제안은 검증 후 확정한다.
